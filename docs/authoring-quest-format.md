# Authoring YAML: инструкция для автора (без программирования)

Связанные документы (для справки):

- `docs/README.md` - карта документации.
- `docs/current-state.md` - что реально работает в репозитории.
- `docs/json-quest-format.md` - “внутренний” runtime-формат (знать не обязательно).
- `docs/cli.md` - как запускать квест из CLI.

Этот документ объясняет, как писать квест в формате **authoring YAML**. Он рассчитан на автора без навыков программирования: вы описываете сцены, текст, варианты выбора и простые “условия/последствия”. Дальше система сама превращает YAML в формат движка и проверяет ошибки.

## 1) Что такое квест в этой системе

Квест — это набор **сцен**. В каждой сцене:

- показывается текст (одна строка или несколько строк);
- иногда предлагаются варианты выбора (choices);
- иногда система автоматически решает, куда перейти дальше (ветвление по условиям);
- иногда сцена завершает игру (финал).

Имена сцен вы придумываете сами (например `intro`, `hallway`, `escape`). По этим именам происходит переход.

## 2) Минимальные правила YAML (самое важное)

- **Отступы важны.** Используйте 2 пробела на уровень (как в примерах).
- Списки начинаются с `-`.
- Если в строке есть двоеточие `:` или начинается с `!`, лучше взять строку в кавычки `"..."`.
- Поля, которых “не знает” формат, считаются ошибкой (это сделано специально, чтобы опечатки не проходили молча).

## 3) Структура файла

Пример “каркаса”:

```yaml
questId: demo_cell
version: 1.0.0
title: Пробуждение в камере
start: intro

vars:
  resolve: 0

flags:
  hasKey: false

scenes:
  intro:
    text: Привет!
    choices: []
```

Поля верхнего уровня:

- `questId` — идентификатор квеста (любая понятная строка, латиница/цифры/подчёркивание лучше всего).
- `version` — версия (обычно `1.0.0`).
- `title` — заголовок квеста.
- `start` — id стартовой сцены (с какой сцены начинается игра).
- `vars` — переменные (числа). Например “решимость”, “деньги”, “здоровье”.
- `flags` — флаги (да/нет). Например “есть ключ”, “договорился со стражником”.
- `textPools` — *необязательно*: глобальные “пулы” фраз (см. раздел про пулы).
- `scenes` — сами сцены.

Примечание: вместо `start` можно написать `startNodeId`, а вместо `vars` — `variables`. Но лучше использовать короткие варианты из примеров.

## 4) Сцены: текст и выборы

### 4.1 Текст сцены

Текст может быть:

1) одной строкой:
```yaml
text: Вы приходите в себя в сырой камере.
```

2) или списком строк:
```yaml
text:
  - Вы приходите в себя в сырой камере.
  - Под дверью виден тонкий луч света.
```

### 4.2 Выборы (choices)

Выбор — это вариант, который видит игрок. У каждого выбора обязательно:

- `id` — стабильный идентификатор (не меняйте его, иначе сохранения/история решений могут сломаться)
- `text` — что увидит игрок
- `goto` — куда перейти после выбора (id следующей сцены)

Пример:
```yaml
choices:
  - id: search_straw
    text: Осмотреть солому
    goto: corridor_decision

  - id: call_guard
    text: Позвать стражника
    goto: corridor_decision
```

## 5) Условия (when): когда выбор доступен

Поле `when` делает выбор доступным только при выполнении условия.

Примеры:

- флаг должен быть **true**:
```yaml
when: hasKey
```

- флаг должен быть **false** (обязательно в кавычках):
```yaml
when: '!hasKey'
```

- сравнение переменной:
```yaml
when: resolve >= 1
```

Можно писать несколько условий списком — тогда должны выполниться все:
```yaml
when:
  - hasKey
  - resolve >= 1
```

## 6) Последствия (do): что меняется после выбора

Поле `do` описывает изменение состояния после выбора.

Примеры:

- установить флаг:
```yaml
do: hasKey = true
```

- установить переменную:
```yaml
do: resolve = 3
```

- увеличить/уменьшить переменную:
```yaml
do: resolve += 1
```

Несколько действий списком:
```yaml
do:
  - hasKey = true
  - resolve += 1
```

## 7) Автоматическое ветвление (branches): “если…, иначе…”

Иногда игрок ничего не выбирает, а система сама решает, куда перейти. Для этого используется сцена с `branches` и `default`.

```yaml
branches:
  - when: hasKey
    goto: escape
default: captured
```

Смысл: если есть ключ — перейти в `escape`, иначе — в `captured`.

## 8) Финальные сцены (result): завершение квеста

Финал — это сцена с `result`:

```yaml
text: Вы выбираетесь на свободу.
result: victory
```

`result` — это метка результата (например `victory`, `defeat`, `neutral` — как вам удобно).

## 9) Пулы текста (textPools): вариативные фразы

Пул — это список фраз, из которого движок выбирает одну. Это полезно для “флэйвора”, газет, случайных реплик.

### 9.1 Локальные пулы (рекомендуется)

Локальные пулы объявляются прямо внутри сцены и действуют только в этой сцене:

```yaml
scenes:
  intro:
    textPools:
      cell_flavor:
        - В углу пахнет плесенью и мокрой соломой.
        - Где-то за стеной капает вода, мерно отбивая время.
    text:
      - Вы приходите в себя в сырой камере.
      - "{{pool:cell_flavor}}"
    choices: []
```

Чтобы вставить фразу из пула, используйте `{{pool:имя_пула}}`. Важно: строку лучше взять в кавычки.

### 9.2 Глобальные пулы (если нужно переиспользование)

Если один и тот же пул нужен в разных сценах — вынесите его наверх в `textPools`:

```yaml
textPools:
  rumors:
    - Говорят, стражник сегодня злой.
    - Говорят, ночью будет смена.
```

Локальные пулы (внутри сцены) имеют приоритет над глобальными, если id совпадает.

## 10) Подстановки в тексте (простые вставки)

В тексте можно показывать значения переменных и условные фрагменты:

- значение переменной: `{{resolve}}`
- условный текст по флагу:
  - `[if hasKey]есть ключ[endif]`
  - `[if !hasKey]нет ключа[endif]`

Пример:
```yaml
text: "Ваш уровень решимости: {{resolve}}. У вас [if hasKey]есть ключ[endif][if !hasKey]нет ключа[endif]."
```

## 12) Частые ошибки

- **Плохие отступы** (YAML “ломается”) — проверьте, что везде 2 пробела.
- **`'!hasKey'` без кавычек** — YAML может воспринять `!` как спец. синтаксис.
- **Переименовали `choice.id`** — сохранения/история решений могут перестать совпадать.
- **Ссылаетесь на несуществующую сцену** в `goto` — валидатор покажет ошибку.
- **Ссылаетесь на несуществующий пул/переменную/флаг** — валидатор покажет, где именно.
